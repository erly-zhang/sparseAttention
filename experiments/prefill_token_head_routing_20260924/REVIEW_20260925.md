## 已完成的静态修复（均待执行验证）

| 优先级 | 发现 | 修改 |
|---|---|---|
| 高 | 旧记录器包在生成桥接层外，total 会包含桥接层保存长输入 JSON 的时间；其 prefill 判断还排除了单 token prompt | 独立入口的 Recorder 使用桥接层已有的单一计时源；保留纯 decode forward 时间和 legacy total-minus-prefill 的区别 |
| 高 | 新方法的 pair 计数只在 sidecar 中，旧汇总器读不到 | 给 online metrics 补充 selected/causal prefill pair 计数和相应稀疏率，明确它们不是硬件执行指令数 |
| 高 | 只验证各条件 doc_id 集合与输入哈希序列，不能发现题目/答案身份变动，也未重新核验保存的 token ID | 加入 doc/prompt/target 哈希的逐 doc_id 对照、输入 token 重算哈希、生成长度和停止分类检查；完整 sidecar 流式读取 |
| 中 | 每个 query chunk 重复 gather 同一头的整段 K/V，并对 allowed.sum 做 Python int 转换导致 GPU 同步 | K/V gather 移至 chunk 循环外；精确 causal pair 计数在设备上累计，每次 attention 返回时转换一次；不改变 Q/K/V、mask、scatter 或重复拼接语义 |
| 中 | 数千条 128k 输入以 Python int 列表同时保存在内存 rows 中，和落盘记录重复 | 正式入口只在磁盘保留完整 input_ids，内存保留摘要；不减少模型 KV cache |
| 中 | 非递增位置到 attention 层才报错，可能已经修改第一层 cache；dense 路径没有相同保护 | model-level guard 在任何 layer forward 前验证位置合法性；显式拒绝未物化/多设备模型 |
| 中 | 旧机器默认 task_config 路径不存在；B/C 可能使用 create_reference 独立创建不对齐的基准 | 提前检查依赖目录；A 必须创建新基准，B/C 必须提供 A 的 reference；仍须后续核验引用文件内容和完整性 |
| 低 | dense 方法元数据也声称 scatter+repeat；缺少生成参数和文本 sidecar | 修正 A 的输出语义字段，记录 generation config/overrides；正式 bridge 接入真实 tokenizer 保存 prediction |
| 低 | 停止条件同时成立时无法只根据末 token 和长度知道唯一原因 | 保存分类优先级：观察到 EOS → 长度达到上限 → 其他 stopping criteria，不称其为唯一实际触发原因 |

对应文件：`routing.py`、`generation_bridge.py`、`recorder.py`、`run_infinitebench.py`、`validate_results.py`。
新增未执行的 `test_review_changes.py` 覆盖身份/输入/长度损坏、缺失与重复行、位置错误时 cache 不变、完整输入只落盘等情况。原有参考测试继续用于核对路由输出和 pair 计数。

## 仍需解决或核验的事项

1. **本次代码未执行。** 统一 Recorder 是新的集成路径，必须走一次原生单 token prompt 和官方合成适配器调用，确认写盘数、计时 scope 与汇总字段一致。现有 `validate_adapter.py` 验证官方 loader/bridge，但尚不覆盖整个 `run_infinitebench.py` 的 Recorder 子类；不能把该测试通过等同于正式入口通过。
2. 真实 InfiniteBench 数据/过滤后的 task YAML/原始 reference 尚未对齐。3493 只是旧专项源码的期望，不是本地数据已验证总数。缺少旧过滤规则时不能直接把官方原始全集称作同一输入。
3. B/C 的 reference 目前只要求显式路径，仍需在正式运行前验证它确实是同任务、同模型/分词器/模板、同截断配置下完成的 A，不能只靠文件存在。
4. 独立校验器强化了跨条件身份核验，但还没有建立每个 lm_eval doc_id 与按长度排序的 generation call 的完整一一对应表。正式结果需补充该映射，或依据保存的原始 request 与输入清单建立可核验映射。不得把 sorted call_index 当 doc_id。
5. SDPA 仅是接口名称，实际 kernel 会随 dtype、GPU、mask 改变。当前短输入 fp16/V100 数据不能预测 bf16/H100 的长输入性能；rectangular pair domain 不能替代 kernel profiler。
6. 对所有 32 层当前保留完整 QKV 和 cache；128k、fp16/bf16 KV 正确下界为 **16 GiB**，加约 15 GiB 权重仍不是峰值显存。单卡 H100-80GB 是候选，需要实测激活、临时 mask、KV 扩容及 allocator 峰值。
7. 本次没有改变算法来改善先前退化输出，没有调参或挑选测试题。仍是原位置 modulo 路由、scatter 后显式重复 M、完整 W_O、所有层启用、标准 dense decode。
8. 单设备以外、chunked prefill、beam/speculative decode、训练仍不支持。checkpoint 的 Llama-3.1 RoPE 和真实尺寸已有历史审计记录，但新修订不能引用旧运行来证明数值一致性。

- 资源：已有且仍有效、空闲的开发 allocation 中 **1 张 V100-32GB**；不新申请资源。若失效或忙碌则停止。
- 范围：原独立小张量/两层随机 Llama 测试 + 新增记录完整性与 guard 测试；随后 1 条明确标注的合成 PassKey，经官方 loader/bridge，A/B/C，各最多 3 个新 token。
- dtype/backend：小模型 float32、SDPA；原有 eager 数值参考保留。正式路由默认显式重复拼接，不启用 summed W_O 作为新实验条件。
- 上限：10 分钟墙钟，最多 1/6 GPU-hour；超时停止本轮验证，不自动扩大资源。
- 输出：新目录 `records/review_20260925_validation/`；合成适配器使用新的 `--out` 路径，不覆盖先前日志。逐条记录命令/退出码及源码哈希。

- 候选：A/B/C、10 任务、期望 3493 题/条件、总 10479 次生成；各任务 budgets 沿用已审计入口，seed=42、batch=1、greedy、chat、131072 总上下文、中间截断。
