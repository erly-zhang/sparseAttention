AutoBlock 完整流程与实现边界

SharePrefill-AE K=3 · token-first

1. 离线分组与逐层执行

AE 从校准样本的 attention map 学习 latent embedding，随后每层独立聚成 3 个 head groups 并固定代表头。推理仍按 Transformer 层顺序传播：当前层生成 mask、完成所有 heads 的 attention、拼接并经过 W_O，其输出成为下一层输入；下一层依据新的 hidden states 重新生成自己的 mask。

2. 构造 Selector Row

每层的 Q 被切成 128-token query tiles。对每个 layer × group × query tile 独立构造一行 selector mask。32K 输入有 256 个 query tiles，因此每个 group 有 256 行。8192 是每一行沿 K 轴的上限，不是全层、全组或全样本共享的预算。

3. 四探针对 Key Token 打分

代表头只负责路由。每个 tile 取位于 1/3、2/3、末尾的三个 Q，并加入全部 128 个 Q 的均值，共四个 probes。每个合法 key token 的分数为 0.2·s1/3 + 0.3·s2/3 + 0.4·slast + 0.1·smean。probes 不替代真正 attention 中的 128 个 Q。

4. Token-first Top-8192

Selector 先屏蔽 query tile 末端之后的未来 keys，再按加权分数选择最多 8192 个 target key tokens。较短历史只能选择当前可见数量。该固定上限是实验中的准确率、稀疏度和 kernel 成本折中，并非理论最优常数。

5. 动态 Block 投影

同一 target token mask 分别投影到 32、64、128-token K blocks。覆盖 target token 比例低于 12.5% 的普通 block 被舍弃；sink 与 local/diagonal blocks 强制保留并计入最终 8192-token 整块预算。比较三种候选的 target coverage，并在距最佳值不超过 2 个百分点的候选中选择最大的 block size。

6. 共享结构，独立 Attention

同一 layer × group × query tile 中的 heads 共享 chosen block size、block mask 和展开后的 K-token IDs，但不共享 Q/K/V 或 attention probabilities。相邻 query tiles 可以选择不同 block size；同一层的不同 groups 也可以不同。

7. Kernel 中的 QK、Causal 与 Softmax

Selected blocks 展开成具体 K IDs，再按固定的 32-K chunks 输入 kernel。每个 head 独立计算 Q[128,d] × K_chunk[d,32]。随后按绝对位置对每个 Q-K pair 施加精确 causal mask，非法 logit 置为 -∞，并跨全部 chunks 做 online softmax 与 P×V。Softmax 会在保留且合法的位置重新归一化到 1，不额外乘启发式 rescale。

8. 如何阅读图中的方格与 Chunk

16×16 方格只是共享 mask 的 16Q×16K 采样切片：一个小格表示一个 Q-K pair 是否参与计算，不是一个 head，也不是 score 大小。32-K chunk 是 kernel 的固定执行粒度，与逻辑 block size 解耦。若最终 selected K 数量完全相同，三种 block size 的 QK 算术量相同；更大 block 主要减少 metadata，并可能改善连续访存。

  • 两级 causal：selector 使用 tile-end 粗粒度边界，kernel 再对 tile 内每个 query 应用精确位置约束。
  • 强制 sink/local 能保护全局锚点与局部依赖，但会占用最终预算，因此普通 blocks 的可用容量会相应减少。
  • 代表头的作用是生成共享路由，不进行一份可供成员 heads 复用的 dense attention；成员 heads 仍分别计算真实 attention。
