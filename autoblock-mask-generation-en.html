Complete AutoBlock Procedure and Implementation Boundaries

SharePrefill-AE K=3 · token-first

1. Offline Grouping and Layer-Sequential Execution

The AE learns latent embeddings from calibration attention maps. Each layer is then partitioned into three fixed head groups with one representative per group. Inference still follows the Transformer stack sequentially: the current layer builds its masks, computes all heads, concatenates them, and applies W_O; the resulting hidden states enter the next layer, which constructs new masks from its own Q/K states.

2. Construct Selector Rows

Each layer's queries are partitioned into 128-token tiles. One selector row is built independently for every layer × group × query tile. A 32K input contains 256 query tiles, hence 256 rows per group. The 8,192-key cap belongs to one such row along the K axis; it is not shared by the layer, group, or sample.

3. Score Key Tokens with Four Probes

The representative head performs routing only. A tile uses the queries at one-third, two-thirds, and the last position, plus the mean of all 128 queries. Each legal key receives 0.2·s1/3 + 0.3·s2/3 + 0.4·slast + 0.1·smean. These probes approximate routing importance; they do not replace the 128 queries in the actual attention computation.

4. Token-First Top-8,192

The selector first excludes keys after the query-tile endpoint, then retains up to 8,192 target key tokens by weighted score. A shorter history can retain only its visible keys. This cap is an empirical accuracy-sparsity-kernel-cost operating point, not a theoretically optimal constant.

5. Dynamic Block Projection

The same target-token mask is projected onto candidate K-block sizes of 32, 64, and 128 tokens. Ordinary blocks covering less than 12.5% target tokens are discarded. Sink and local/diagonal blocks are forced and counted inside the final 8,192 expanded-token budget. We measure target coverage for each candidate and choose the largest block size within two percentage points of the best coverage.

6. Shared Structure, Head-Specific Attention

Heads in one layer × group × query tile share the chosen block size, block mask, and expanded K-token IDs, but not Q/K/V values or attention probabilities. Neighboring query tiles may choose different block sizes, as may different groups in the same layer.

7. QK, Exact Causal Masking, and Softmax

Selected blocks expand into K IDs and enter the kernel in fixed 32-key chunks. Each head independently computes Q[128,d] × K_chunk[d,32]. The kernel then applies an exact absolute-position causal mask to every Q-K pair, sets illegal logits to -∞, and performs online softmax and P×V across all chunks. Softmax renormalizes the retained legal positions to sum to one; no additional heuristic rescaling is applied.

8. Reading the Matrix and Chunks

The 16×16 grid is only a sampled 16Q×16K slice of the shared mask: one cell indicates whether one Q-K pair participates. It is neither a head nor a score magnitude. The 32-key chunk is a fixed kernel execution tile, independent of logical block size. If all candidates expand to the same K count, QK arithmetic is unchanged; larger blocks mainly reduce metadata and may improve memory locality.

  • Two causal stages are used: the selector applies a coarse tile-end boundary, while the kernel enforces the exact position constraint for every query.
  • Forced sink/local blocks protect global anchors and local dependencies but consume the final budget, reducing capacity for ordinary blocks.
  • The representative head generates shared routing; it does not compute a dense attention result reused by member heads. Every member head still computes its own attention.
